Auth handshake

connect :25010 → read <Status><Init/>
<Req><Protocol version="1"/>
<Req><Authenticate phase="challenge"/>
  ← nonce
digest = b64( SHA256(
   "user:pass:nonce:cnonce" ))
   each field cut to 44 chars
<Req><Authenticate phase="response"
   user cnonce digest/> → <Rsp/>

The 44-char truncation trips naïve clients — a full-length nonce fails even with the right password.

control <Req><Call url="Media_Pause"/>   → <Rsp/> success

Actions (Media_Play/Pause, Sound_Mute, Sound_IncreaseVolume, Media_NextTrack) are invoked with Call — EXLAP is not read-only. There is no Set verb.

Method: the 260-name superset comes from the analyzed plugin's add<name>P17_exlap_ServerCtxt symbols. Measured union membership comes from isolated live Dir captures; the 511 selectable credentials are precomputed offline without publishing the master secret. Registration gates come from exhaustive execution of the plugin's initServer branch graph across all 16 combinations of Vehicle Data, Navigation, Rear Seat Entertainment and High Performance FSID states. The reference state predicts exactly the 168 URLs returned live by OPEN-FFFFFF. Measured credential counts overlap and must not be added together. The registration gate and Read-versus-Call interface kind are known for every entry; only the isolated credential assignment of Rear Seat Entertainment URLs awaits an equipped-unit capture.

This is a cross-unit research atlas, not a promise that every object exists on every Porsche/VW head unit. Firmware family, FSIDs, installed hardware, brand and region can all change the live directory. No standalone EXLAP schema XML was found under /eso, /mnt/app, /etc or /mnt/efs on the analyzed unit; its object/interface schema is constructed by libexlap_plugin.so and exposed as runtime XML responses.
